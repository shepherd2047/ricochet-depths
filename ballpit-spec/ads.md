# 广告点规格（demo 第一关）

> 依据 TikTok 小游戏的广告文档写成：Unity SDK 只有**激励视频**和**插屏**两种，没有横幅。
> 官方只给定性建议：插屏放在关卡完成、页面切换这类自然停顿处，不要一启动就弹，不要连续弹，不要在关键操作时打断。频次由开发者自己控制。
> 现阶段**先用 2 秒占位广告**，等拿到 TikTok Unity SDK 和广告位 ID 再换成真广告。

## 1. 激励视频（玩家主动点）

| # | 时机 | 按钮 | 奖励 | 上限 |
|---|---|---|---|---|
| R1 | 死亡时进入"复活询问"状态（spec §1 状态列表） | "Watch ad · Revive" 和 "Give up" | 血量恢复到上限的 50%；清掉离玩家最近的 2 行敌人（不给击杀奖励） | 每局 1 次 |
| R2 | 升级三选一，放在重抽按钮旁边 | "Ad · Free reroll" | 免费重抽一次，不花金币，也不推高付费重抽的价格 | 每局 3 次 |
| R3 | 熔炉，放在"免费升级"选项上 | "Ad · +1 upgrade" | 这次"免费升级"的件数 +1（上限 5，spec §5.4 ①），多出的一件按同样规则补抽；看完后卡片上的件数立刻更新，玩家再决定选哪一项 | 每次熔炉 1 次 |

- 只有看完（`isEnded == true`）才发奖励。中途关闭的话不发奖励，按钮恢复原状（R1 回到复活询问）。
- 达到上限后隐藏这个按钮。
- 结算时的"金币翻倍"**暂时不做**：demo 没有局外成长，金币带不出这一局。

## 2. 插屏（自动弹，严格控制）

- **唯一时机**：结算界面上点 "Restart" 或 "Home" 之后、切换画面之前。
- 第一局永远不弹；启动后 180 秒内不弹；两次插屏之间至少隔 180 秒；刚看过激励视频的那一局，结算后也不弹。
- 战斗中、弹窗打开时、启动时，一律不弹。

## 3. 通用规则

- 播放广告时：战斗时钟暂停（和暂停菜单一样），背景音乐和音效静音，广告关闭后恢复。
- 广告不可用或加载失败时：激励视频的按钮变灰，并提示 "Ad not available"；插屏直接跳过。任何情况下都不能卡住流程。
- 所有上限和间隔都放在一个配置对象里（`AdConfig`），方便以后调整。
- 广告调用统一走一个接口 `IAdService`，提供 `ShowRewarded(placement, onDone(bool watched))` 和 `ShowInterstitial(onDone)` 两个方法。现在由占位实现 `PlaceholderAds` 负责，以后换成 TikTok SDK 的实现（`TT.CreateRewardedVideoAd` / `TT.CreateInterstitialAd`，每次展示都新建一个实例，先 `Load()` 再 `Show()`，用完 `Destroy()`）。

## 4. 占位广告（现在就做）

- 全屏黑底，中间显示 "AD"、广告位名称和 2 秒倒计时。2 秒内不能关闭。
- 激励视频：倒计时结束后右上角出现 "×"，点击后回调 `watched = true`。倒计时期间点 "Skip" 则回调 `watched = false`，用来测试中途关闭的流程。
- 插屏：倒计时结束后自动关闭。
- 编辑器和测试构建里可以打开"广告失败"开关，用来测试失败的流程。
- 机器人对局（bot）一律选择不看广告，保证平衡测试的结果和以前可以对比。
