# 视觉风格规格（净室 · 抽象参数）

> 本文件由分析方根据参考作的渲染设置和资源统计写成，只记录**抽象参数**：相机、光照、色调范围、面数预算、动画方式和渲染管线。
> 不描述任何具体角色、敌人或场景的造型。所有模型、贴图、图标都必须原创。
> **不要用参考作的截图、模型或贴图做参考或 AI 生成的输入。** 情绪板只能用其他来源：无关的游戏、摄影、概念图。
>
> 参考作是横屏 PC 游戏，本项目是竖屏手机游戏。凡是和画幅有关的数值，已经按竖屏换算成建议值。

---

## 1. 整体观感：低多边形 3D 加像素界面

| 层 | 参考作的做法 | 本项目建议 |
|---|---|---|
| 场景（坑壁、地面、装饰） | 低多边形 3D 模型，按"左侧 / 右侧 / 中段 / 拐角"切成可拼接的模块，每个关卡主题一套 | 每个主题分**起始段 / 中段 / 尽头段**三套，每套 2–3 块左右墙段（共 6–9 块），外加 2–3 个装饰件。**没有天花板**：走廊一直延伸进雾里，地面和墙会持续滚动（见 spec §1.3a），所以墙段沿走廊方向必须首尾无缝相接 |
| 英雄 | 低多边形 3D，每个约 600–1100 顶点，所有英雄共用一张贴图图集 | 每个 ≤ 1000 顶点，共用一张 1024 图集 |
| 普通敌人 | 低多边形 3D，每个约 90–400 顶点，同一主题的敌人共用一张 512 图集，另配一张发光贴图 | 每个 ≤ 400 顶点，每个主题一张 512 图集 |
| 精英和 Boss | 约 1000 顶点 | 每个 ≤ 1500 顶点 |
| 球、拾取物、图标、界面 | **像素风精灵图**，每单位 16 像素（部分 25），大多数是 16×16 的小图；点采样，不做平滑 | 相同的做法：16×16 像素风，点采样 |
| 特效 | 粒子系统加着色器，按颜色渐变图上色 | 相同的做法（见 §5） |

**核心观感**：3D 场景和单位**偏暗、偏灰、低饱和**，球和特效**高亮、高饱和、会发光**。玩家视线总是被球和特效拉走，场景只负责提供纵深和氛围。

## 2. 相机

- **透视相机，俯视约 40°**（用户在 2026-10-19 先定 30°，同日看过场景方的对比图后改为 40°；参考作是 0° 正对，本项目有意不同），从玩家身后上方看向坑内，离棋盘中心的距离按下面的取景边距算（场景方按 7×9 棋盘实测：边距 1 格约 17.4 单位，边距 1.5 格更远一些，以场景方的 ASSEMBLY.md 为准）。
- **取景边距 1.5 格**：棋盘两侧各有 1 格宽的道具带（在碰撞线外，只放装饰），墙面在道具带外侧。最近一行两侧要露出道具带和约半格墙面，所以边距取 1.5 格，不要只留半格。
- 参考作横屏下的垂直视野约 63°。竖屏建议**垂直视野 60–70°**，保证 7 列的初始棋盘（§1 规格）在最窄的屏幕上左右各留约半格边距。俯视之后，棋盘远端会因为透视变窄，要以远端那一行能装下 7 列为准。
- 玩法逻辑仍在一个平面上按 2D 做（碰撞、反弹、格子都在棋盘平面上），只是相机斜着看这个平面。**3D 感来自俯视角加上两侧坑壁朝远处延伸**，单位和墙会投下实时阴影。
- 瞄准：触摸点要从屏幕坐标投射到棋盘平面上，再换算成角度，不能直接用屏幕坐标。
- 近裁剪面 0.3，远裁剪面 1000。远处被雾吞掉（见 §3）。
- 棋盘扩张时（Boss 回合），相机后拉，让新的列数刚好装进视野，3 秒内缓动完成。
- 界面另用一台正交相机叠加在上面。

## 3. 光照与雾

- **一盏主方向光**：白色，强度 1，略微从上往下打（约 10° 俯角），**开启软阴影**。
- **三色环境光**（天空 / 地平线 / 地面），都偏暗、偏冷：
  - 天空：约 RGB(54, 58, 66)，暗灰蓝；
  - 地平线：约 RGB(29, 32, 34)；
  - 地面：约 RGB(12, 11, 9)，接近黑的暖灰。
- **线性雾**：从 30 单位开始，到 50 单位全浓。雾色和相机背景色相同，都是**暗蓝灰，约 RGB(38, 41, 55)**。远处的坑壁会融进背景色。
- 局部点缀光：可以加带颜色的点光或聚光（参考作有一盏偏黄绿的聚光），用来营造关卡主题的气氛。

## 4. 色调范围（按 HSV 统计）

统计的是参考作贴图的主色，**只用作明暗和饱和度的范围**，色相由本项目的各个主题自定。

| 对象 | 明度 V | 饱和度 S | 特征 |
|---|---|---|---|
| 场景贴图 | 10–33%，地面和墙面主色取上限附近（约 25–33%，用户 2026-10-19 要求提亮） | 15–45% | 很暗；主色是低饱和的橄榄绿、苔绿，加深蓝黑的阴影 |
| 敌人贴图 | 大面积 0–30%，小块点缀 55–85% | 点缀色 35–45% | 暗色身体，加少量**亮黄的强调色**（眼睛、武器、标记） |
| 敌人发光贴图 | 只有极小面积有亮色 | — | 只有眼睛和标记这类小点发光 |
| 英雄贴图 | 多数在 12–40%，少量达到 50% | 有一块高饱和的深色（S≈90%，V≈12%） | 深色衣着，加一两个醒目的颜色块，方便和敌人区分 |
| 球和特效 | 60–100% | 40–80% | 最亮、最饱和的一层，每种属性一条颜色渐变 |

**规则**：
- 场景 < 敌人 < 英雄 < 球和特效，亮度依次递增。
- 敌人和英雄靠**色相**区分。建议敌人用暖色、暗色加黄色点缀，英雄用冷色或带一个高饱和的标识色。
- 每个关卡主题只换场景的色相和点缀色，明暗范围保持不变。

## 5. 球与特效

- **每种属性一条 64×2 的颜色渐变贴图**，着色器按亮度或时间去查这张图。冰、火、雷、毒、铁、血等各一条。
- **渐变的结构**：
  - 冰：暗青 → 青绿 → 亮黄白；
  - 铁：黑 → 暗紫灰 → 浅金；
  - 雷：暗紫灰 → 暖灰 → 亮米白。
  - 共同点：**暗端很暗，亮端接近白**，这样配合 Bloom 能出"发光"的感觉。
- 球本体是 16×16 像素精灵，外加拖尾（大多数属性有专属拖尾）和光环。
- **受击反馈**，由单位着色器统一处理：
  - 命中闪白（混合系数随时间衰减）；
  - 冰冻：表面叠一层冰色；
  - 流血：用噪声贴图叠出血迹；
  - 每个单位带一个随机种子，让同类单位的效果不同步。
- **后处理**：开启 Bloom，阈值设在只有球和特效会触发的亮度，场景和单位不应该发光（敌人眼睛除外）。

## 6. 动画

- **敌人**：低多边形模型加**烘焙顶点动画**。待机只有 2 个姿势循环，走动、出招和死亡各是一段很短的动画。可以用 GPU 实例化一次画很多个。
- **"像素感"的动作**：动画帧率低，大约 8–12 帧/秒，不插值，和像素风界面统一。
- **英雄**：一个带骨骼的模型，用分层动画，**上半身负责瞄准和射击，下半身负责走动**，两层同时播放（见 §6.1）。
- **死亡**：模型碎裂（参考作的着色器支持表面裂纹），或缩小加粒子爆开。

### 6.1 英雄动作集（参考作的结构，抽象描述）

参考作的英雄是带骨骼的蒙皮模型，用状态机加混合树驱动。**武器一直端在手里朝前**，任何时候都不会张开双臂。整套动作分成相互叠加的两层：

**上半身层（瞄准）**：三个状态，每个状态都是按瞄准方向混合的三向混合（偏左、正前、偏右）。
| 状态 | 进入条件 | 时长与循环 |
|---|---|---|
| 待机瞄准 | 没有移动输入 | 约 0.9 秒循环；轻微呼吸，武器跟着瞄准方向转 |
| 边走边瞄 | 有移动输入 | 约 0.9 秒循环；上半身随步伐起伏，武器保持指向瞄准方向 |
| 射击 | 每次发射球时触发一次 | 约 0.2 秒；短促的后坐（武器上抬、肩膀后顿），播完回到待机瞄准或边走边瞄 |
- 瞄准方向用一个连续参数表示（偏左 → 正前 → 偏右），三个方向的姿势平滑混合。超出这个范围的转向由整个身体的朝向负责。
- 射击的触发和回落都很快（过渡约 0.05 秒以内），连射时每发都能看出顿挫。

**下半身层（走动）**：一个二维混合，参数是移动方向的 x 和 y。
| 方向 | 动作 |
|---|---|
| 无输入 | 原地站稳（双脚着地，重心略微起伏） |
| 前 / 后 | 前进步 / 后退步 |
| 左 / 右 | 侧向横移步 |
- 下半身只控制腿和骨盆，上半身层只控制腰以上，所以可以边后退边朝前射击，不会互相打架。
- 走动时身体朝向不随移动方向转，始终朝瞄准方向；腿用横移步、后退步来配合。

**单独的整身状态**（覆盖上面两层）：
| 状态 | 触发 | 说明 |
|---|---|---|
| 死亡 | 游戏失败 | 约 0.8 秒，不循环，停在最后一帧 |
| 胜利或结束 | 游戏胜利 | 约 0.9 秒循环的庆祝姿势 |
| 抛投（可选） | 少数角色的抛物线发射 | 约 0.9 秒，不循环 |
| 受击 | 掉血时 | 参考作**不用骨骼动画**，而是用闪白加一次很短的击退位移；本项目也这样做 |

**本项目的要求**：
- 动作帧率可以低（10–12 帧/秒、不插值），但**层叠和混合必须保留**：上半身和下半身分开，瞄准方向分左、前、右三向。
- 静止时的默认姿势是"双手持发射器、枪口朝前"，绝不能是 A 字或 T 字张臂姿势。

## 7. 界面与像素资源

- **像素尺寸**：每单位 16 像素；常用尺寸 16×16（图标、球）、18–37 像素（小部件）、64 像素（大图标）。
- **全部点采样**，不做平滑和抗锯齿；按整数倍缩放。
- 界面打包成一张图集（参考作是 2048×1024）。
- **数字**用像素字体位图；正文可以用 SDF 字体。
- 英文界面，见项目约束。

---

## 8. 渲染管线与包体

- **管线**：Unity URP（通用渲染管线）。参考作是 3D 前向渲染，界面另用一个 2D 渲染器。
- **竖屏手机建议**：
  - MSAA 关闭；HDR 只在要用 Bloom 时开启；
  - 阴影只投在主方向光上，距离 30；
  - 贴图压缩：WebGL 用 ASTC 或 ETC2；
  - 图集：英雄 1024，每个主题的敌人 512，每个主题的场景 1024，界面 2048×1024。
- **一个关卡主题的资源预算**：场景约 8 块墙段（每块 ≤ 2000 顶点），敌人 8–12 种，Boss 1 个。贴图总量不超过 4 张 1024 等效。

## 9. 素材生产建议（实现方）

1. **先定情绪板**：只用无关来源，然后写下本项目自己的色相方案（每个关卡主题 1 个主色加 1 个点缀色）。
2. **场景和单位模型**：
   - 用 AI 文生 3D（Tripo、Meshy、混元 3D）或 Blender 手做，再减面到上面的预算以内；
   - 统一用"图集 + 少量平涂色块"的贴图方式，便于控制明暗范围。
3. **动画**：用 Mixamo 绑骨骼、取动作，再烘焙成顶点动画，或者直接用骨骼动画（数量少时可以）。
4. **像素资源**：用 16×16 的画布手绘，或者让 AI 出图后缩小、按调色板量化、手动修整。
5. **验收**：所有原创资源都要和参考作对照检查，**确认没有撞造型**。这一步由分析方做，实现方不看参考作。
